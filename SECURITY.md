# Security Policy — SWI V2

## Reporting

Report suspected vulnerabilities privately via GitHub Security Advisories on this repository when public disclosure would create risk.

Include: affected component, reproduction steps, impact assessment, and any PoC appropriate for private review.

## Classification

Distinguish:

- **Vulnerability** — confirmed exploitable weakness with evidence
- **Design limitation** — documented boundary of claims
- **Implementation defect** — bug relative to contract/tests
- **Documentation error** — claim mismatched to code/evidence
- **Evidence gap** — behaviour not yet tested/CI/audited
- **Theoretical concern** — unproven path

Do not call every concern a vulnerability without evidence.

## M11 note

The M11 seal is a historical evidence record. Licence or documentation changes do not alter its meaning. New technical changes require new tests, CI, and (if applicable) a new seal event.
